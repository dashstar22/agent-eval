# 评测方法、结果与局限

AgentEval 评价的是一次受控运行：先冻结问题、参考行为、工具预期和评分配置，再保存 Agent 的实际执行与 Judge 理由。本文给出 2026-11-16 的双配置回归结果，并解释分母、失败和证据缺失的含义。

## 真实回归结果

两次运行使用同一份 30 题合成已见回归集，A 配置使用 `qwen-plus`，B 在同一隔离售后实例中将聊天模型切换为 `qwen-flash` 后重启。Judge 固定为 `qwen-plus`，量表为 `agenteval-rubric-v1`，规则为 `agenteval-rules-v1`，正确性、相关性和任务完成度的阈值均为 4。

| 指标 | A：qwen-plus | B：qwen-flash |
|---|---:|---:|
| 冻结 / 执行 / 评价用例数 | 30 / 30 / 30 | 30 / 30 / 30 |
| Agent 执行成功 / 失败 | 29 / 1 | 23 / 7 |
| 质量通过 P / 失败 F / 未判定 U | 25 / 5 / 0 | 10 / 20 / 0 |
| 有效通过率 P/(P+F) | 83.33% | 33.33% |
| 可判定覆盖率 (P+F)/N | 100% | 100% |
| 成功供应商模型元数据覆盖 | 29/30 | 18/30 |
| 真实 Judge 成功评分 | 30/30 | 30/30 |

两次批次均为 `COMPLETED`，表示全部冻结用例已处理。它不表示所有业务任务成功，也不表示每题都成功请求了模型。上表是本项目冻结口径和 AI Judge 下的结果，不是独立人工准确率。

原始回答、工具、上下文、模型尝试、Judge 响应和比较结果保存在 [脱敏回归记录](evidence/g7-real-ab-20261116.json)。[结构与覆盖复核记录](evidence/g7-results-audit-r2-20261116.json) 对保存记录进行离线复算，得到结构一致性通过、真实覆盖未完全验证；这类结构检查不等于额外的质量样本。

## 如何理解两版差异

两次运行的数据、Judge 和规则指纹一致，可以按相同问题查看差异。30 题的正确性、相关性和任务完成度都有共同有效配对；依据充分性只有 12 题共同有效，比较时使用这 12 对，而不是相减两侧各自有效集合的均值。

18 对题目在双方都有成功供应商响应元数据，可以核实请求和返回模型从 `qwen-plus` 变为 `qwen-flash`。这 18 对包含最终业务失败、但前面已有成功模型响应的题，不能等同于 18 对业务任务全部成功。整批实际版本状态仍为 `UNVERIFIED_CHANGE`。

本次对照有以下限制：

- **预算混杂。** A、B 顺序执行并共用源端调用预算。B 后段包含调用额度拒绝、模型不可用及降级追问，结果下降不能全部归因于模型能力。
- **样本有限。** 30 题是自编的合成已见回归题，用于检查业务行为与功能退化；不代表未知真实用户分布，也不证明统计显著性或生产效果。
- **Judge 偏差。** 参考行为和测试由 AI 辅助整理，质量评分来自 AI Judge；A 与 Judge 使用同源模型，尚无独立人工质量标注。
- **版本覆盖不足。** A 的 H08、B 的 H08 都走确定性追问分支，没有新请求模型；B 另有 11 题没有成功供应商模型响应元数据。模型别名对应的供应商不可变快照未知。
- **用量不完整。** Agent 用量为 `PARTIAL`，Judge 用量完整；没有有效价格配置，费用为 `null`，不能解释为免费或零消耗。

因此，这次结果适合说明评测链路如何记录成功、失败与缺失证据，不足以给两个模型做纯能力排名。

## 保留的失败案例

| 用例 | 已保存事实 | 能说明的问题 |
|---|---|---|
| A / D04 | `searchKnowledge` 返回 `HIT / MATCHED`，实际模型上下文标为完整；最终回答仍称“依据未能确认”，正确性为 1 分 | 检索命中和上下文完整不保证最终任务完成，需要继续核对回答与 Judge 理由 |
| A / D22、B / D01 | 最终状态为 `MODEL_TIMEOUT`；A / D22 在超时前已经有成功模型响应 | 模型成功元数据与最终业务成功是不同事实 |
| B / D02、D05、D06、D14、D15、D16 | 最终为 `MODEL_CALL_LIMIT` | 调用预算会影响整批结果，不能把技术限制当作纯质量差异 |
| A、B / H08 | `NO_MODEL_REQUEST`，确定性追问 | 合理的不请求模型分支不应伪装成真实推理，也不应直接叫作模型失败 |

上述回答、低分和执行失败均按原样保留。页面中的人工原因字段与 Judge 结果分别存储；自动化操作产生的备注不升级为独立人工复核。

## 评分口径

### 程序规则

六项确定性规则分别检查执行完成、回答非空、预期工具出现、工具技术结果、响应耗时和工具名称集合。默认工具来源为 `CHAT_TOOL`，服务端协调动作另存。

工具名称匹配只评价集合，不评价顺序、参数或重复次数：

| 输入 | 含义 |
|---|---|
| `expected_tools=null` | 不检查预期工具 |
| `expected_tools=[]` 且 `exact` | 不允许调用工具 |
| 非空集合与 `contains` | 包含指定工具即可，允许额外工具 |
| 非空集合与 `exact` | 实际名称集合必须完全一致 |
| 实际工具为 `null` | 轨迹未知，不能当作已证实没有调用 |

工具技术成功率使用“明确正常完成 /（明确正常完成 + 技术失败）”。合法业务拒绝和未知分别计数，轨迹完整性单列。工具技术结果与业务任务是否符合参考行为独立评价。

### LLM Judge

Judge 对正确性、相关性、任务完成度和适用时的依据充分性给出 1—5 整数分及理由。默认前三项阈值为 4，这是项目可配置起点，不是行业标准。合理追问、正确拒答或遵守页面确认要求，都可以符合参考行为。

依据充分性需要本轮完整实际模型上下文。最终引用子集只能说明有限的引用支持范围，不能冒充完整上下文；不适用的指标保留 `NA`，不补 0 分。

默认单次 Judge 超时 60 秒、单题总时限 360 秒、响应上限 2 MiB。可重试的临时 API 或格式错误至多重试一次，认证错误不重试。每次请求、原始响应、解析结果、用量和错误独立保存。实际调用还受剩余预算限制，这些数值是保护配置，不是性能实测。

问题、回答和上下文作为待评数据发送，后端使用冻结量表与阈值合并判定。模型评分仍可能受注入或偏差影响，不将提示词视为绝对防护。

### 用例结论

默认必评项为执行完成、回答非空、正确性、相关性和任务完成度。指标状态与用例结论分开：

| 条件 | 用例结论 |
|---|---|
| 任一必评项已有确定失败 | `FAIL` |
| 没有确定失败，但有必评项缺失或评分错误 | `UNDETERMINED` |
| 所有必评项通过 | `PASS` |

因此，Agent 超时与 Judge 故障同时出现时，仍保留已知执行失败；Judge 故障不会改写 Agent 已经成功返回的事实。

## 固定分母与缺失数据

假设冻结 `N=30`，其中通过 `P=20`、失败 `F=5`、未判定 `U=5`：

| 统计 | 计算 | 结果 |
|---|---|---|
| 总量核对 | 20+5+5 | 30 |
| 有效通过率 | 20/(20+5) | 80% |
| 可判定覆盖率 | (20+5)/30 | 83.33% |
| 全量中已通过的比例 | 20/30 | 66.67% |

80% 只描述 25 条可判定用例中的通过率。5 条未判定仍在冻结总数中；不能称为“三十题准确率 80%”。没有可判定用例时，通过率为 `null`；空数据的覆盖率也为 `null`。进行中的报告标为临时统计，中断后保留原 N。

每项质量均分同时给出有效样本数。耗时均值只使用成功执行的 Agent，超时数、分母和超时率另列。两版比较按每个指标分别取共同有效题，缺分不补零，也不直接相减不同集合的均值。

Agent 与 Judge 的 Token 分账，Judge 重试逐次计入。前置轮次按执行身份去重，回放不重复记原消耗；缺失尝试会使用量标为已知部分。没有有效模型价格、币种、计价单位和生效来源时，费用保持 `null`，不按字符估算 Token。

## 读取与复算

下列查询都是只读，不调用模型：

- `GET /api/v1/runs/{run_id}/scoring-summary?score_set_id=...`：固定分母统计，省略评分集时选择 ORIGINAL。
- `GET /api/v1/case-runs/{case_run_id}/scoring?score_set_id=...`：同一道题的指标、结论和 Judge 尝试。
- 工作台的报告、评测详情和 Badcase：按运行和评分集读取相同持久化记录。

RESCORE 会创建新的评分集并调用 Judge，旧回答、旧结论和原 Agent 用量保留。更换阈值或 Judge 后，应明确选择评分集再比较。

本地工程检查可按 [本机运行](quickstart.md#本地检查) 执行。前端构建记录见 [构建回执](evidence/g7-delivery-build-20261116.json)，其中失败尝试与包体警告保留。单元测试、结构复算、HTTP 协议替身与真实模型评测分别提供不同证据，测试通过不等于业务质量通过。
